# CareerPilot 求职准备 Agent

CS353FZ 五人团队项目。面向大学生实习求职，结合个人经历、目标岗位和检索到的知识资料，提供有依据的岗位分析、准备计划和模拟面试。

当前阶段：需求与设计初稿。仓库暂未包含可运行的应用；本文中的功能和技术方案是开发基线，不能视为已实现。

## 产品范围

用户上传简历及项目说明，导入目标岗位描述（JD）。系统提取岗位要求，检索个人经历与知识库，展示匹配依据及待补充信息，生成准备计划。用户确认后，计划保存为可跟踪任务。基础闭环完成后，再加入针对个人项目和岗位要求的模拟面试。

- P0：个人资料管理、JD 导入、带出处的匹配分析、准备计划预览与确认保存。
- P1：任务进度跟踪、文本模拟面试与反馈。
- 本期不包含：自动投递、全网岗位爬虫、语音面试、视频情绪分析和多 Agent 集群。
- 未检索到经历时，标记“现有资料未体现”，并允许用户补充；不得编造经历、证书、项目结果或面试表现。

## 五人分工

成员姓名和 GitHub 账号由团队确认后补充。A–D 是职责编号，不代表职级。

| 成员 | 主要责任 | 独立交付物 | 协作边界 |
| --- | --- | --- | --- |
| 项目负责人（本人） | PRD、总体架构、数据库设计、需求取舍、整体验收、最终测试与部署 | PRD、架构图、ER 图及数据字典、验收场景、部署环境与交付材料 | 审核公共接口及 Schema 变更；统一负责最终集成测试和上线 |
| 组员 A：前端与用户体验 | 资料上传、JD 导入、分析结果与证据展示、计划看板、文本面试界面 | 可运行的页面、组件、API 客户端、加载与失败状态、前端接入说明 | 只通过业务 API 访问数据；使用样例响应先开发界面，不直接接模型或数据库 |
| 组员 B：业务后端与应用数据 | 用户认证、文件上传和私有存储、资料与岗位 CRUD、任务状态、计划确认与保存、面试记录、API 集成 | 业务 API、权限检查、数据模型实现、索引初始化、配置示例、后端接入说明 | 按负责人设计实现数据库；调用 C 的索引模块和 D 的 Agent 模块，不复制其检索或推理逻辑 |
| 组员 C：RAG 与知识库工程 | 文档解析、文本切分、向量化、个人经历与公共知识索引、检索、来源定位、删除同步 | 可独立调用的入库与检索模块、证据数据结构、知识库来源清单、检索样例 | 保留文档版本和原文位置；按用户隔离检索；不负责对外用户系统或最终求职结论 |
| 组员 D：Agent 与求职流程 | JD 要求拆解、资料缺失追问、证据匹配、工具调用、计划生成、文本面试提问与反馈 | Agent 执行模块、结构化输出、工具契约、提示词版本、运行轨迹及异常处理 | 经业务后端提供的工具读写数据；计划写入必须经过用户确认；不直接维护索引或另建数据库模型 |

最终测试与部署由负责人承担，不单独分配给四位组员。每位开发者仍需在交付前自查自己的模块，提供启动方式、样例输入输出和已知问题；这属于模块交付，不另设测试岗位。

## 模块协作

```text
A 前端 → B 业务 API → D Agent → C RAG 检索
                  ↘ MongoDB / 私有文件存储
B 资料上传 → C 解析及建索引 → 就绪后供 D 调用
D 生成计划草稿 → A 展示并确认 → B 保存正式计划
```

1. 负责人先确定需求边界、数据模型与 API 草案。
2. A、B 根据同一份 API 契约开发；C、D 根据同一份内部工具契约开发。
3. 第一条联调链路：简历上传 → 资料就绪 → JD 导入 → 分析任务 → 引用展示。
4. 第二条链路：生成计划 → 用户确认 → 保存任务 → 修改任务状态。
5. 最后扩展文本面试，由负责人执行整体验收与部署。

模块发生变更时，同时维护实现、接口文档和对应 Issue。报告按实际贡献分写：A 负责交互设计，B 负责业务实现，C 负责 RAG 方法，D 负责 Agent 流程，负责人负责总体设计、评测整合和交付。

## Git 协作要求

**先建 Issue，再开工作分支；禁止直接向 `main` 提交或推送，所有改动通过关联 Issue 的 PR 合入。**

- `main` 保存经审查的稳定版本；`dev/` 是文档目录，不是集成分支。
- 团队分支示例：`feat/42-jd-import`、`fix/43-citation-location`、`docs/44-api-spec`；Codex 分支使用 `codex/44-api-spec`。
- Commit 格式：`type(scope): 简明描述`；正文使用 `Refs #<Issue编号>` 关联任务。
- PR 描述使用 `Closes #<Issue编号>` 关联本次完成的 Issue；部分完成使用 `Refs #<Issue编号>`。
- 至少一位其他成员审查，负责人或约定维护者合并；不得自行批准自己的 PR。
- 完整要求与命令示例见 [Git 协作规范](dev/07-Git协作规范-git-workflow.md)。
