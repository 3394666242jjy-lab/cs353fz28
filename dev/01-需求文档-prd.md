# CareerPilot 需求文档

状态：v0.1 设计初稿，待负责人评审。产品需求由负责人维护；任何范围变更先记录 Issue，再更新验收标准。

## 用户与问题

目标用户是准备技术实习的大学生。用户通常已有简历和项目经历，但难以把岗位要求对应到具体证据，也难以把“需要准备什么”转化为可执行计划。

产品帮助用户整理已有信息、补充遗漏、安排准备任务。分析反映用户提供的资料，不预测录用概率，也不参与企业招聘筛选。

## 核心用户故事

| 编号 | 用户故事 | 优先级 | 验收条件 |
| --- | --- | --- | --- |
| US-01 | 上传并管理简历及项目说明 | P0 | 支持有文本层的 PDF 和 UTF-8 TXT/Markdown；单文件不超过 10 MiB；显示处理中、就绪、失败；失败可重试 |
| US-02 | 查看和纠正资料提取结果 | P0 | 原文与提取内容可查看；用户修正保存为新版本并重建索引；旧结果可识别为过期 |
| US-03 | 粘贴目标 JD | P0 | 保存原始文本；提取岗位名称、必需及加分要求；用户可纠正；不依赖招聘网站爬虫 |
| US-04 | 获得带证据的匹配分析 | P0 | 按岗位要求展示“有证据支持／部分支持／资料未体现”；每条证据可回到文档及位置；无依据不编造 |
| US-05 | 生成并确认准备计划 | P0 | 输入目标日期和每日可用时间；任务工时总和及每日安排不超约束；先预览，确认后保存；重复确认不重复创建 |
| US-06 | 跟踪准备任务 | P1 | 用户可更新待办、进行中、已完成状态；刷新后进度保留 |
| US-07 | 进行文本模拟面试 | P1 | 根据选定 JD 和用户项目提问；记录回答；最多 5 个主问题、每题最多 1 次追问；反馈区分用户事实与参考知识 |
| US-08 | 删除个人资料 | P0 | 删除后不再出现在搜索结果中；相关原文件与索引清理可重试；关联分析显示来源不可用或过期 |

扫描 PDF、图片识别、DOCX 解析可作为扩展，第一版应明确提示暂不支持的格式，而不是静默生成空资料。

## 主要流程

1. 登录并上传资料；后台完成解析、分块和索引。
2. 用户检查资料，导入并确认 JD。
3. 创建分析任务；仅使用已就绪的资料版本。
4. Agent 拆解要求，检索证据；证据不足则追问或标记资料未体现。
5. 展示分析及引用；生成有时间约束的准备计划草稿。
6. 用户确认计划，创建正式任务；后续可跟踪任务或开始文本面试。

## 功能边界

- 第一版单 Agent，工具与模块可独立实现。
- 不自动投递、修改外部招聘账号或联系招聘人员。
- 不凭空补全技能、学历、工作年限、项目指标和经历。
- JD、简历及知识资料中的文字均为待分析数据，不得覆盖系统工具权限和行为约束。
- 用户必须能够区分“资料中确认的事实”“用户待确认的信息”和“系统建议”。

## 非功能要求

- 个人文件、索引、分析及面试按用户隔离；公共知识库单独标记来源。
- 耗时操作使用异步任务；前端能查看状态和失败原因，不以长时间空白等待代替进度。
- 每条证据记录文档、版本、位置和片段标识；更新资料后可判断结果是否过期。
- 不记录完整简历、原始回答和密钥到普通应用日志；通过受控数据存储保留业务记录。
- 支持可配置的模型、检索和超时预算；上限与失败状态在 API 和架构中定义。

## 评测与验收

负责人建立独立保留的验收集，成员可提供开发样例。建议首批包含 20 个要求匹配案例、10 个无证据案例、5 个时间受限计划案例和 2 个用户隔离场景；数量是项目建议，不是课程硬性规定。

比较不使用 RAG、基础 RAG、RAG 加工具调用三种方案。对文档较短的案例补充全文上下文基线。记录证据命中、引用是否支持结论、无依据陈述、任务完成情况、耗时和模型用量。结果必须来自实际运行；此文不预填效果数字。

发布前须完成：P0 场景验收、用户隔离与删除验证、部署及回滚演练。性能目标在首次原型测量后写入 Issue，由负责人确认，避免凭空承诺。
