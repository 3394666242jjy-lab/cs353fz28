# CareerPilot 需求文档

状态：v0.4 设计基线与 M1 契约候选版；2026-10-22 将有文本层 PDF 上传及 Python 解析纳入 M1，业务实现与整体验收仍待完成。产品需求由负责人维护；范围变化同步更新验收标准，日常协作遵循 Git 规范。

## 用户与问题

目标用户是准备技术实习的大学生。用户通常已有简历和项目经历，但难以把岗位要求对应到具体证据，也难以把“需要准备什么”转化为可执行计划。

产品帮助用户整理已有信息、补充遗漏、安排准备任务。分析反映用户提供的资料，不预测录用概率，也不参与企业招聘筛选。

## 首轮范围与后续阶段

M1 完成合成数据的有文本层 PDF 与 UTF-8 Markdown/TXT 上传、Python 后端解析、JD 导入、真实向量检索、三类匹配分析和可点击原文引用。PDF 引用显示原文件页码，文本引用显示行号；用户无需手动转格式。登录使用本地种子账号，任务通过最小 Celery/Redis 分发并轮询状态。M1 缺失信息写入结果，不暂停追问；不要求计划、面试、真实 SSE、混合检索或云资源先就绪。

M2 补齐完整 P0，包括资料修改/删除、计划确认、人工恢复、SSE、Outbox 等可靠性与检索增强实验；M3 扩展任务看板与模拟面试。扫描件 OCR 另作扩展。P0/P1 是最终交付优先级，不是要求所有 P0 在第一轮一次做完。具体任务与验收见 [M1 开工计划](08-M1开工计划-kickoff-plan.md)。下文主要流程和非功能要求描述完整产品目标，M1 以本节及开工计划的明确子集为准。

## 主要流程

1. 登录并上传资料；后台完成解析、分块和索引。
2. 用户检查资料，导入并确认 JD。
3. 创建分析任务；仅使用已就绪的资料版本。
4. LangGraph Agent 拆解要求，检索证据；证据不足可暂停追问，用户补充后继续，或选择保留“资料未体现”；前端通过 SSE 展示业务进度。
5. 展示分析及引用；生成有时间约束的准备计划草稿。
6. 用户确认计划，幂等创建正式任务并恢复执行；后续可跟踪任务或开始文本面试。

## 功能边界

- 第一版单 Agent，工具与模块可独立实现。
- 不自动投递、修改外部招聘账号或联系招聘人员。
- 不凭空补全技能、学历、工作年限、项目指标和经历。
- JD、简历及知识资料中的文字均为待分析数据，不得覆盖系统工具权限和行为约束。
- 用户必须能够区分“资料中确认的事实”“用户待确认的信息”和“系统建议”。

## 非功能要求

- 个人文件、索引、分析及面试按用户隔离；公共知识库单独标记来源。
- 耗时操作经 Celery/Redis 分发，权威状态保存在 MongoDB；重启和重复投递不会重复创建用户可见资源，失败原因明确。
- Agent 的补充信息与计划确认使用持久化状态，等待用户时释放 Worker；正常恢复不重置累计执行预算。
- 前端通过鉴权 SSE 展示阶段、等待输入与结果，断开时查询任务快照恢复，不在 URL 传递访问令牌。
- 每条证据记录文档、版本、位置和片段标识；更新资料后可判断结果是否过期。
- 不记录完整简历、原始回答和密钥到普通应用日志；通过受控数据存储保留业务记录。
- 支持可配置的模型、检索和超时预算；上限与失败状态在 API 和架构中定义。
- 最终部署目标为阿里云 ECS；Docker Compose 管理云端服务，MongoDB 使用托管实例、文件放私有 OSS。正式发布由负责人确认触发，不等同于本地联调完成。

## 评测与验收

负责人建立独立保留的验收集，成员可提供开发样例。建议首批包含 20 个要求匹配案例、10 个无证据案例、5 个时间受限计划案例和 2 个用户隔离场景；数量是项目建议，不是课程硬性规定。

分两组比较，避免把检索与工具调用的收益混在一起：

1. 检索组：固定生成模型、文档切分及问题集，比较仅向量、混合检索、混合检索加 Rerank。记录有标注证据的问题的 Recall@k、引用正确性和检索耗时；无证据问题单独检查是否误给个人经历证据。
2. 端到端组：比较不使用 RAG、基础 RAG、RAG 加 Agent 工具调用。短文档另设全文上下文基线；检查任务完成、约束满足、引用依据、无依据陈述、耗时及用量。

先用开发集调整切分、召回条数与重排配置，再用独立保留验收集报告结果。记录模型、提示词、检索配置和资料版本，不在同一验收集上反复调参。结果必须来自实际运行；此文不预填效果数字。Langfuse 为后续可选工具，固定评测集与人工核对先完成。

发布前须完成：P0 场景验收、用户隔离与删除验证、SSE 断线恢复、队列重试和重复消息处理、用户确认暂停/恢复、ECS 部署与回滚演练。性能目标在首次原型测量后由负责人确认并留档，避免凭空承诺。
