# CareerPilot 开发规范

状态：v0.2 团队开发约定。Git 分支、Commit 和 PR 规则单独见 [07 Git 协作规范](07-Git协作规范-git-workflow.md)。技术方案以 02 文档为准，尚未实现的功能不能在 PR 或报告中宣称完成。

## 公共约定

- PRD 定义功能和验收，API 文档定义前后端契约，数据库文档定义集合与生命周期。
- 先约定输入输出与样例，再并行实现。接口不确定时在 Issue 中讨论，不靠猜测改对方代码。
- 前端使用 React/TypeScript，服务端使用 Python/FastAPI/Pydantic；Agent 使用 LangGraph，队列使用 Celery/Redis；具体运行时及依赖版本在脚手架中锁定并提交锁文件。
- 统一 UTF-8、LF 和文件末尾换行。格式化器与 lint 配置在脚手架中确定；不提交未确认版本的工具配置。
- 代码目录在搭建时确认，建议 frontend、backend、backend/rag、backend/agent、backend/contracts；目录是实现规划，当前尚未创建。

## 接口与类型

- JSON、Python 和数据库字段统一 snake_case；前端内部变量可 camelCase，边界显式转换。
- 请求和响应使用明确类型／模型验证；不以任意字典绕过关键字段校验。
- 异步操作区分 HTTP 接收成功和任务执行成功；前端完整处理 queued、running、waiting_for_input、succeeded、failed。Celery 任务结束不等于 LangGraph 业务已完成。
- 用户身份来自认证上下文，资源归属在业务和检索层均验证。
- 外部服务调用设置超时和可控重试；限制并发，防止无限循环与重复费用。

## 前端 A

API 调用集中封装，云端使用 Nginx 同域 `/api/v1`，不在组件中散落真实服务地址。页面覆盖空数据、处理中、失败、重试、无证据、资料过期等状态。证据展示支持跳转原文位置；无法定位时明确说明。计划确认和重复点击正确处理，刷新后可恢复已有任务状态。

使用 fetch 流处理鉴权 SSE，令牌只放请求头。按 id 去重、按游标恢复业务事件，终态和等待输入时停止无限重连；历史过期读取快照后再继续。展示检索阶段、工具调用摘要和结果，不展示模型隐藏推理。P0 先完成可靠业务进度，token 级动画作为后续扩展。

## 业务后端 B

路由负责 HTTP 校验与响应，业务服务负责权限和一致性，存储层负责查询。数据库和 OSS 凭据不可进入前端。上传检查大小、类型及实际可解析性，使用服务端对象键，不将原始文件名直接拼接成存储路径。使用版本校验、幂等计划确认和可恢复任务。

MongoDB 保存权威任务状态，Celery/Redis 负责消息分发。execution 与 dispatch_events 同事务写入，重复投递通过状态版本、投递 ID 和资源幂等处理。任务消息只含必要标识，不携带完整简历或模型输入。SSE 读取持久化业务事件，不能只用 Redis Pub/Sub 承担恢复。运行租约、重试次数、可见性超时和失败补偿需有真实故障样例。

## RAG C

每个片段带来源、版本和实际位置。区分个人经历和公共知识；个人资料按用户隔离。记录解析器、嵌入模型、维度及切分参数。更新或删除资料时同步索引，避免返回失效来源。检索为空返回空结果和原因，不生成假证据。返回的 quote 必须来自实际原文。

Qdrant 作为可重建检索索引，MongoDB/OSS 保留来源。向量、关键词混合及 Rerank 路径使用同一份权限与版本过滤；候选融合后再重排，输出引用必须能回到原片段。用固定生成模型与问题集比较 dense、hybrid、hybrid_rerank，不以数据库品牌或向量分数替代效果验证。

## Agent D

提示词与工具定义纳入版本管理；使用结构化输出并做代码校验。工具白名单只开放当前任务所需能力；模型输出不直接变成数据库查询或任意命令。文档和 JD 是数据，不能覆盖系统权限。任何能力匹配结论引用真实证据；资料不足时追问或标记未知。正式计划由用户确认并经业务 API 保存。

使用 LangGraph 明确节点、条件边、状态与 Checkpoint。thread_id 由服务端分配并与用户、execution 绑定；暂停等待输入时释放 Celery Worker，后续按当前 interrupt/checkpoint 恢复。恢复可能重放节点，所有外部写入经业务服务幂等处理；确认计划后的节点只完成状态，不再次生成用户已确认的内容。

区分用户恢复与技术重试；预算跨恢复累计。删除或更新来源后重新校验权限和版本；不可依赖 Checkpoint 中的旧副本绕过删除状态。

不记录或要求模型暴露隐藏推理过程。可展示工具调用名称、检索来源、业务状态和用户可读的简明结论依据。

## 配置与数据

使用环境变量管理服务配置，样例只保留占位值。不得提交真实简历、身份证明、访问令牌、数据库转储或生产日志。开发样例明确标注合成数据。知识库保留来源与可使用范围记录；不把来源不明内容当作个人经历。

Langfuse 为可选观测接入，默认不向外部平台上传个人原文或面试回答。先完成本地结构化事件及固定评测集，需要上传时通过显式配置、脱敏和访问控制验证。模型、检索、提示词及图版本应进入评测记录，不能记录密钥或隐藏推理过程。

## 容器与发布交付

各成员提供自己模块的运行、依赖、健康检查及配置需求。负责人统一整合 Compose、Nginx、GitHub Actions 和阿里云发布，四位开发成员不另设部署岗位。前端静态文件、API/Worker、Redis 和 Qdrant 使用对应容器；MongoDB 使用托管实例，文件使用私有 OSS。

PR 检查不接触生产凭据；main 构建精确 SHA 的镜像，正式 ECS 更新由负责人手动触发。当前仓库只有文档，不提交假定可运行的 Compose 或空转 CI 来冒充完成；脚手架就绪后补齐真实配置与验证。

## 模块交付

每位成员提交前自行验证模块的代表性成功与失败场景，检查编译／类型／格式等项目现有检查，不把未完成的基础自查留给负责人。PR 写明实际执行的命令或手工步骤；尚未执行的检查诚实标明。

最终集成测试和部署由负责人执行。A 提供页面及联调说明，B 提供运行和存储初始化说明，C 提供入库与检索样例，D 提供工具及分析样例。任何模拟响应须标注，不能作为真实效果或完成证据。

## AI 辅助与文档

成员对提交内容的正确性和理解负责。使用 AI 生成或修改代码、图表、文档时，在对应 PR 记录工具、用途及核验方式，为课程声明提供依据。AI 内容不能代替真实实验与用户反馈；日志、截图和报告中的效果数据必须可追溯。
