## 3. 自检步骤

### 3.1 资料管理（01 资料准备）

1. 登录后上传一份 PDF/Markdown/TXT，等待状态变为“已就绪”。
2. 在「M2 / 资料管理」选择资料，查看提取文本。
3. 修改文本并保存：
   - 成功：显示新版本号，并提示正在重建索引。
   - 409：提示版本冲突，不覆盖他人修改。
4. 删除资料：确认后显示 `deleted` 与 purge 状态；列表刷新后不再出现（或标记删除中）。
5. 未登录或使用他人资料：接口返回 401/404，页面显示错误，不展示内容。

### 3.2 岗位版本（02 目标岗位）

1. 首次点击「保存岗位」：`POST /jobs` 创建 v1。
2. 修改 JD 后按钮变为可点，点击「保存新版本」：`PATCH /jobs/{id}` 携带 `expected_version`。
3. 返回 409 时：页面自动 `GET /jobs/{id}` 加载最新版本并提示“本次修改未覆盖”。
4. 后端未实现 PATCH（501）时：提示“本次修改未保存”，不伪造成功。
5. 岗位更新后，若已有分析结果，页面提示“旧分析可能已过期，请重新分析”。
6. 分析时复用已保存的岗位 ID，不会重复创建岗位。

### 3.3 计划（04 准备计划）

1. 选择目标日期、时区、每日可用分钟数。
2. 点击「生成计划草稿」：调用 `POST /plans` 并轮询执行，直到 `waiting_for_input` 后读取 `GET /plans/{id}`。
3. 草稿明确标注“未保存为正式任务”；确认后调用 `POST /plans/{id}/confirm`，展示 `plan.tasks` 中的正式任务。
4. 重复点击确认不会重复创建任务（按钮在确认后禁用，接口幂等由后端保证；刷新后仍是已确认状态）。
5. 刷新页面或切换步骤后，从 `careerpilot.plan_draft` 恢复草稿/已确认计划和表单值；生成过程中刷新也能用已保存的 `execution_id` 继续轮询。
6. 样例计划不写后端，界面标注“样例计划”。

### 3.4 澄清恢复（02 目标岗位 → 真实分析）

1. 分析进入 `waiting_for_input` 时显示恢复面板，而不是报错；面板展示服务端问题与恢复点信息。
2. 可填写补充说明；自由文本只作为待核实说明，不会自动成为经历证据。
3. 可勾选「不补充资料，按现有资料继续」，对应 `continue_without_evidence=true`。
4. 需要新资料时到「01 资料准备」上传并勾选，回到本页后自动识别新增资料并随回答提交 `document_ids`。
5. 点击「提交回答并继续」调用 `POST /executions/{id}/resume`，成功后继续 SSE/轮询；409 冲突或恢复点失效时自动重新同步任务状态。
6. 刷新页面后仍会从保存的执行 ID 恢复等待面板；`interrupt_id`/`checkpoint_id` 由服务端快照/事件返回。

### 3.5 SSE 与恢复（02 目标岗位 → 真实分析）

1. 启动分析后，进度优先通过 `GET /executions/{id}/events` 推送（浏览器 Network 中为 `text/event-stream`）。
2. 刷新页面：从 sessionStorage 读取最后 `event_id`，以 `after_event_id` 续传，不重复展示旧事件。
3. 后端返回 410（事件历史过期）：自动改用 `GET /executions/{id}` 轮询，并在页面上提示“已切换为轮询”。
4. 后端未提供事件流（404/405/501）：立即回落到轮询，分析流程不中断。
5. 分析完成或失败后关闭事件流，避免重复请求。
6. 退出登录、切换账号时清空岗位与事件游标，避免串号。

## 4. 与后端的契约对接

| 能力 | 前端调用 | 后端未就绪时的表现 |
| --- | --- | --- |
| 资料文本更新 | `PUT /documents/{id}/text` | 501/404 → 错误提示，不本地伪造版本 |
| 资料删除 | `DELETE /documents/{id}` | 501 → 提示删除接口未就绪 |
| 重新索引 | `POST /documents/{id}/reindex` | 501 → 提示 |
| 岗位更新 | `PATCH /jobs/{id}` | 501 → 提示未保存；409 → 拉最新版 |
| 计划生成 | `POST /plans` | 501 → 提示；样例模式可用 |
| 计划查询/确认 | `GET /plans/{id}`、`POST /plans/{id}/confirm` | 草稿用 `draft_tasks`，确认后用 `tasks`；响应 `plan/execution_id/resumed` |
| 澄清恢复 | `POST /executions/{id}/resume` | 501/409 有明确提示；answer 为 `{text, continue_without_evidence, document_ids}` |
| 事件流 | `GET /executions/{id}/events?after_event_id=` | 404/405/501 → 轮询回落 |

约定：

- 所有请求带 `Authorization: Bearer <token>`。
- 错误统一读取 `error.code` / `error.message`；401 触发全局重新登录事件。
- 资料版本冲突返回 409；事件游标过期返回 410；资料未就绪返回 409 `DOCUMENT_NOT_READY`。
- 前端不会把样例数据当真实结果提交；样例模式只在本机内存/sessionStorage 中。
