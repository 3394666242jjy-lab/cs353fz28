# M3.1 切分与三方向知识库基线

日期：2026-11-13，Refs #34。目标岗位：AI 产品经理、全栈开发、Agent 开发。这里记录已运行的原型、素材和实测，同时列明在线接线的后续工作。

检查结果：新增核心检查 13 项通过；启用真实 MongoDB 与既有检索生命周期检查后，完整后端 **537 passed，无跳过**，66.31 秒。Ruff 检查与格式通过。没有前端/API 契约改动，因此未新增页面联调或重新生成 OpenAPI；新增离线结构诊断已接入 CI。AI 辅助用于源码、素材整理和设计草稿，所列测试及 Embedding 调用均已实际执行。

## 1. 先按材料结构切分

| 材料 | 切分单元 | 需要共同保留的内容 |
| --- | --- | --- |
| 个人 PDF | 原页内段落 | 原页码、实际提取文本，继续沿用 M2 严格 PDF 解析 |
| 项目 Markdown | 标题层级 + 段落 | 项目背景、动作与结果，不能把推荐知识补成经历 |
| AI 产品材料 | 小节 + 指标/评估表 | 指标名称、定义、分子分母、窗口和适用情境 |
| 全栈技术文档 | 标题 + 代码/接口说明 | 完整代码块、参数与错误条件；不按空行切断函数 |
| Agent 工程材料 | 状态/工具/故障小节 | 前提、输入输出、幂等与恢复边界 |

切分策略根据材料格式选择，岗位标签用于过滤与评价，不强迫每个岗位使用完全不同算法。本轮只新增 Markdown 结构原型，未声称已解析网页 DOM、PDF 表格、扫描图或 DOCX。

`rag/structured_chunking.py` 实现：

- 标题层级路径、段落装包、完整 fenced code / Markdown table 保护。
- 默认软目标 600 字符，硬限制 6000 字符；长普通段落可按原文偏移拆分，超长代码/表格明确拒绝并要求复核，绝不截断后假装完整。
- 原子块可超过软目标，报告单独计数；没有把字符数当作 token 数。后续模型上下文仍需按实际 tokenizer 再检查。
- LF 归一化后的精确 `[char_start, char_end)` 和行号、标题路径、父片段范围、配置版本，以及由来源版本/内容/范围派生的稳定 ID。
- `text` 是精确原文切片；`embedding_text` 可附标题路径，只用于检索输入，不作为原文 quote。
- `parent_id/parent_start/parent_end` 为父子检索预留上下文。当前只提供元数据；自动父片段扩展与 token 预算分配尚未接入线上检索。

M2 `TextLocator` 只有行号，不能准确表示一行中拆出的局部片段。M3 在真正接入业务前，必须增加来源 span 契约或保证返回原完整行，不能把新偏移静默塞进旧行号接口。已有 M2 资料和引用保持不变，新策略另起配置/集合和文档版本。

## 2. 固定结构诊断集

`backend/tests/data/m3_chunking/` 包含三个自行编写的合成文档，各对应一个方向；18 个问题及唯一原文锚点在 `questions.json`。语料指纹、定位还原及完整代码/表格均有检查。评测只索引三个 `.md`，不把问题、锚点标注、结果 JSON 或示例预期答案放入索引。

这是**小规模开发诊断集**，不是独立保留的效果验收集：每个方向只有一个文档，一些问题指向同一小节，没有统计独立性。后续必须增加同主题不同来源、版本冲突、无答案、跨岗位、长代码和指标表，再建立独立保留集。

比较配置：M2 段落基线 target600；M3 结构方案 target300、600、900。所有方案使用相同问题与原文，按岗位过滤候选。词法模式使用 BM25 型编码；真实 Embedding 模式使用已配置的百炼 `text-embedding-v4@1024`，在内存中计算余弦排序。两种模式分开保存，未修改生产或开发 Qdrant 集合。

## 3. 实际结果

真实 Embedding 结果：

| 配置 | 切块数 | 代码/表格完整 | Span Recall@1 | Span Recall@3 | MRR |
| --- | --- | --- | --- | --- | --- |
| M2 paragraph 600 | 6 | 0/3 | 1.0000 | 1.0000 | 1.0000 |
| M3 structure 300 | 18 | 3/3 | 0.8333 | 1.0000 | 0.9167 |
| M3 structure 600 | 15 | 3/3 | 1.0000 | 1.0000 | 1.0000 |
| M3 structure 900 | 15 | 3/3 | 1.0000 | 1.0000 | 1.0000 |

这里的命中是“检索片段完整包含标注的原文 span”，不是回答准确率。四档均逐字可还原且非空字符覆盖率 100%，没有超过硬上限。M2 的 0/3 表示三个原子结构都未完整位于同一个 chunk，不表示其文本被丢弃。

词法诊断的 Recall@1 分别为 0.9444 / 0.8889 / 1.0000 / 1.0000，与真实 Embedding 结果不能混算。逐题排名、span、源文件指纹和测量边界见 [词法记录](experiments/m3-chunking-lexical.json)、[真实 Embedding 记录](experiments/m3-chunking-embedding.json)。

当前决策：结构600可作为下一轮实验起点，**不替换 M2 默认切分器**。300 出现了首位命中下降；600 与 900 在这组语料中得到相同分块，样本无法区分二者。不能把满分解释为三岗位通用最优配置，更不能宣称生产 RAG 或模型回答已经达到满分。

## 4. 知识素材与来源治理

[knowledge](../knowledge/README.md) 已整理 13 个一手来源与中文摘要。按岗位可重叠分组：AI 产品经理 5 条、全栈 6 条、Agent 9 条。内容覆盖需求与指标、AI 风险/评价、React/HTTP/事务/服务认证/镜像构建，以及工作流、interrupt、持久化和 MCP。

来源清单保存链接、岗位、主题、适用版本、核验日期、整理版本与内容 hash。摘要属于项目编辑整理，不是上游原文快照；`reference_only` 明确禁止将其转成个人经历证明。当前可读取和词法查询这些卡片，但公共向量入库、来源撤回/API 和在线版本迁移仍待 M3.2。

后续入库契约至少包含：`source_id/version/url/content_hash`、原始格式、`roles/topics/language`、正文/摘要类型、原始 span、标题路径、父片段 ID、parser/chunking/embedding 版本及发布/撤回状态。建议个人索引和共享公共索引使用独立集合与服务接口，避免依赖某个可漏传的 corpus 参数。

新资料先进入候选清单，核验权威性、时效、使用方式和主题覆盖；去导航、去近重复、保留结构后在隔离集合构建与检查，最后发布清单版本。未发布版本不参与检索。撤回先阻断查询，再重试物理清理；已有学习结果显示来源失效。更新来源时按新版本并行构建，不覆盖原引用。

## 5. 下一轮验收

- Agent：匹配判断只能引用真实个人证据；公共引用只解释知识/建议。模型改变角色、身份或工具权限的指令不得生效。
- 检索：跨角色及版本过滤、无答案拒答、细粒度匹配与父上下文扩展分别测量；既要看召回，也要看上下文体积和引用支持。
- 切分：增加多页 PDF、嵌套代码、超长表格、重复标题和中英混排；不能只测短 Markdown。
- 运行：记录真实模型版本、请求/成本/耗时与错误；当前切分实测不包含生成、网络向量库、端到端预算与并发恢复。

## 6. 复现

```powershell
uv run --project backend pytest backend/tests/test_m3_knowledge.py -q
uv run --project backend python scripts/m3_chunking_eval.py --output tmp/m3-lexical.json
uv run --project backend python scripts/m3_chunking_eval.py --mode embedding --output tmp/m3-embedding.json
uv run --project backend python scripts/m3_knowledge_demo.py --catalog --role agent_engineer
```

Embedding 模式会用本机已配置的模型服务处理合成文本，产生实际 API 调用；词法模式无需密钥。源码和提交不包含密钥、原始私人资料、运行数据库或被后移的面试实现草稿。
