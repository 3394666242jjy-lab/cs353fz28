# 合成 AI 产品经理知识案例

本文件为自行编写的结构测试素材，不是用户经历，也不是外部官方原文。

## 需求定义

先描述用户、触发情境、当前工作方式和任务结束条件，再讨论是否需要生成式 AI。这个合成案例要求产品团队先记录用户准备材料时的真实障碍，而不是先决定使用某个模型。能由固定规则处理的需求，应有可比较的规则基线。

访谈结论不能直接替代线上结果，模型能力展示也不能直接替代用户价值。产品需求应写清输入来源、可接受的错误、人工纠正方式、隐私边界和不处理的场景。需求版本改变后，验收集也需要记录相应变化，避免把不同目标下的结果放在一起比较。

## 指标与成本

任务完成率的分母是进入约定任务流程的有效尝试次数，分子是满足明确结束条件的尝试次数。记录时需要固定时间窗口、失败定义和重试口径，不能只统计模型返回了文字的请求。完成率、延迟和单次成功任务成本要分别记录。

| 指标 | 作用 | 注意事项 |
| --- | --- | --- |
| 任务完成率 | 检查用户目标是否达成 | 先固定分子与分母 |
| 人工纠正率 | 检查输出是否需要返工 | 区分纠正内容和纠正格式 |
| 单次成功任务成本 | 记录达到结果的总开销 | 失败与重试也计入开销 |
| 响应延迟 | 观察交互等待 | 报告分位数而非只有均值 |
| 来源可核对率 | 检查引用是否支持结论 | 不能把相似文本当正确证据 |

## 评估与发布

离线评估先固定输入、标注规则和任务边界，再比较不同方案。调整提示词和检索参数所用的开发样例，不能同时冒充独立保留的验收集。这个合成流程要求先小范围发布，保留人工反馈和回滚方式，再观察真实使用中的变化。

上线后的好坏应结合产品任务、质量和运行约束一起判断。模型版本、提示词版本、知识来源版本及检索配置都需要留档。评价报告中必须区分确定性结构测试、模型实际调用结果和人工复核，不得把离线替身当成真实用户测试。

## 信任与解释

当系统没有足够证据时，显示缺少什么信息，并允许用户补充或退出。参考知识应该用来源链接和适用版本解释；用户自述与系统建议分别标注。这个合成情境不使用模型对人的性格或录用概率做判断。
