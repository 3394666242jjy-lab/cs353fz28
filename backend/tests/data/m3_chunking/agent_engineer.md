## Workflow 与动态 Agent

任务路径和验收规则明确时，可以先用代码规定节点和路由。需要根据工具结果选择下一步时，再引入有边界的动态决策。这里的合成架构使用一个状态图协调资料匹配和学习建议，不因为增加角色名称就自动创建多个独立 Agent。

## 工具权限

工具参数不允许包含任意 user_id、数据库查询或图节点名称。身份从服务端请求上下文取得，文档版本由可信业务服务固定。模型只能建议已注册的工具调用，参数校验、超时、重试和写入确认由程序控制。

## Checkpoint 与恢复

在暂停等待用户输入前保存图状态和恢复点标识。恢复时校验身份、来源版本、当前状态、interrupt 和 checkpoint，并沿用累计活动预算。不能因为恢复就把工具调用次数和模型请求次数清零。

节点恢复时可能重新运行节点中的部分代码，因此外部写入需要幂等键。把模型请求、待确认草稿与正式业务写入分开，可以减少重放时重复计费或重复创建任务的风险。图状态保存成功也不等于外部业务事务已经完成；两者要通过可查询记录与受保护的状态迁移协调。

```python
# 合成伪代码：说明顺序，不是可执行恢复适配器。
draft = generate_or_load_draft(execution_id)

# 只有 API 复核并保存了明确确认，才能执行正式写入。
confirmed = require_saved_confirmation(execution_id)
save_tasks_once(confirmed.idempotency_key, draft)
```

## 个人证据与公共知识

个人资料通道只用于判断用户提供的经历是否支持岗位要求；公共知识通道用于解释概念、给出学习建议和参考材料。即使公开教程说明了某项技术，也不能据此把用户的匹配状态改成有证据支持。引用需要保留来源类型、版本、位置与实际片段。
